# Bilingual: English and French

Partyfox is bilingual. **Every screen, game, feature and piece of content ships in
English and French at once**; a change that adds words in one language only is
not done.

## The language comes from the URL

- English pages have no prefix (`/same-page#room`); French ones live under `/fr`
  (`/fr/same-page#room`). A link always carries its language, so link previews
  (bots send no language) show the right card.
- Each French page is a one-line twin of the English one: `app/fr/<route>/page.tsx`
  re-exports `app/<route>/page.tsx`, and `app/fr/<route>/layout.tsx` re-exports the
  English layout (or adds French metadata). `lib/i18n/lang.test.ts` fails when an
  English page has no twin. `/admin` and `/api` are English only.
- `components/LangFromPath.tsx` (root layout) puts the page's language in context;
  `useLang()` (`lib/i18n/useLang.tsx`) reads it anywhere in a client component.
- `lib/i18n/headScript.ts` runs before paint: an explicit choice from the switch
  (`localStorage` `partyfox.lang`) wins; with none, a French browser on an English
  link goes to `/fr`. It also sets `<html lang>`.
- `components/LangSwitch.tsx` is the EN/FR switch (a hard navigation to the same
  page in the other language, keeping the `#room` code).

## Words

- Write a component's words with `texts({ en, fr })` (`lib/i18n/text.ts`): English
  sets the shape, French must match it key for key (TypeScript enforces it). Use
  functions for anything with a number or a name: `round: (n: number) => ...`.
- Read them with `const t = useText(TEXT)` in a client component, or `TEXT[lang]`
  where the language is a parameter (server metadata, pure helpers).
- Keep a game's words next to its UI: `components/<slug>/text.ts`. Shared words:
  next to the shared component. Never hard-code a user-visible string in JSX,
  `aria-label`, `title`, `alt`, `placeholder`, `document.title` or a canvas.
- Plurals: `plural(lang, n, one, other)` (French says "0 point"). Numbers and
  lists: `formatNumber`, `formatList`. Dates and times: `Intl` with `LOCALES[lang]`.
- **Links**: site paths go through `useLocalHref("/regions")`, `LocalLink`, or
  `gamePath(slug, lang)` / `roomHref(slug, code, lang)`, so a French page never
  links to an English one. Entering a room stays a hard navigation (`<a>`).
- Game names are brands, the same in both languages (Same Page, Detour, Rank &
  File...); so is Partyfox. Descriptions, pitches and rules are translated.

## French style

- Casual, warm, **tu** (never vous): "Invite un ami", "À toi de jouer".
- Neutral international French that reads naturally in Québec and in France; no
  anglicisms where a common French word exists, no slang from one region only.
- Avoid gendered forms for the player: not "Tu es prêt ?" or "prêt·e", but
  "C'est parti ?"; not "Invité par Léa" but "Léa t'invite".
- French typography: a space before `?` `!` `:` `;` and inside « », using a
  narrow no-break space (` `) before `?!;` and a no-break space (` `)
  before `:` and inside « ». Straight apostrophes are fine.
- French runs ~20% longer: check the layout at phone width in both languages.

## Content

- A room's **content language** (questions, words, prompts) is the game state's
  `lang`, picked by the host, defaulting to the creator's interface language.
  It's separate from the interface language: a French player can play an
  English quiz.
- Content banks exist in both languages (`questions.json`, `words.json`, Same
  Page's `prompts.json` + `prompts.fr.json`, Co-Counsel's `cases.json` +
  `cases.fr.json`); tests check both.
- Proper names keep their official French title when there is one (films,
  books, games: "Le Voyage de Chihiro"), otherwise the original.

## Checking it

- `npm test` covers the twins and the helpers.
- `ui-review`: screenshot changed screens at `/...` **and** `/fr/...`.
