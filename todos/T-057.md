Pure, game-agnostic metrics in lib/analytics/metrics.ts over a snapshot {rooms, guests, now}; lib/analytics/gameRoomAdapter.ts maps games/* + users/*/rooms into it (so it can become a reusable package later); vitest fixtures in metrics.test.ts. GET /api/admin/stats returns aggregates only. Metrics: (1) Rooms live now = >=1 presence online:true, split playing (lastActive < 2 min) vs waiting, per game, with a list (code, game, name, seats, online, age) feeding T-058's Close button. (2) Players per game = distinct uids per gameSlug from users/*/rooms (persistent; members is cleared on leave), all-time/7d/30d by addedAt; plus rooms created per game (meta.createdAt). (3) Play time v1 = lastActive - createdAt span, labelled approx. (T-059 makes it exact). (4) Return rate = % of guests with room entries on >=2 distinct days, plus came-back-within-7d; UI caveat: cleared storage = new guest. UI: app/admin/page.tsx + components/admin/, KPI row + per-game table + live list, refresh every 30s, fetch in effects (no clock reads in render). Use dataviz + ui-review skills.
